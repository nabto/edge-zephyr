# install tools:

Follow the guide at https://docs.zephyrproject.org/latest/develop/getting_started/index.html

# Initialise project using git clone first

```
source ~/zephyrproject/.venv/bin/activate

mkdir zephyrworkspace
cd zephyrworkspace
git clone git@github.com:nabto/edge-zephyr
cd edge-zephyr
west init -l .
```


# Demo application

Since we need to use MDNS and internet access for a good demo it is easier to
use a development board with Ethernet than using a qemu emulator and have the
hassle with trying to configure it to provide a good user experience.

```
west build -p always -b stm32f746g_disco samples/simple_coap
west flash
```

Open a terminal and use the zephyr shell.


# Running on posix_sim

Posix sim a posix implementation of zephyr which can run on. The implementation
uses networking through a layer 3 tap interface and a psuedotty for stdin and
stdout.

Building:

```
west build -p always -b native_posix_64 samples/simple_coap
```

Running:

The demo uses a tap interface the tap interface can be setup with
`./setup-net.sh` the outgoing interface needs to be set to the desired outgoing
interface on the system.

```
west build -t run
```

Screen can be used to connect to the pseudotty such that it is possible to use
the shell. `screen <pseudotty>` e.g. `screen /dev/pts/17`

## Problems building with sdk-nrf and TF-M

When building a firmware using sdk-nrf with TF-M enabled the configuration made
in prj.conf is applied both for the application and the tfm binary. This gives
some challenges as a custom configuration for MbedTLS is needed.

When setting the configuration options

```
CONFIG_MBEDTLS_USER_CONFIG_FILE
CONFIG_MBEDTLS_CFG_FILE
```

These settings gives alternative names to the mbedtls configuration files, but
they are autogenerated by the build system. And the configuration is applied
both the the TF-M build and the application build, but they are 2 different
builds with different MbedTLS configurations.

If the configuration option `CONFIG_GENERATE_MBEDTLS_CFG_FILE=n` is applied the
configuration files are not generated. If we could set this option for only the
application build but not for the TF-M build then we could provide custom
MbedTLS configuration files for the application build. This is however not
possible to specify for only the application build, so when the option i
specified it affect both the TF-M and application build. But there does not seem
to ba a way to inject a header file into the build system which the TF-M build
uses without it affecting the application build.

Since the TF-M build uses a different MbedTLS configuration file than the
application we can hack a solution together by pasting the following content
into `nrf/subsys/nrf_security/configs/nrf-config-user-empty.h`

```
#define MBEDTLS_ASN1_WRITE_C
#define MBEDTLS_ASN1_WRITE_C
#define MBEDTLS_BASE64_C
#define MBEDTLS_BIGNUM_C
#define MBEDTLS_CIPHER_C
#define MBEDTLS_ECDH_C
#define MBEDTLS_ECDSA_C
#define MBEDTLS_ECP_C
#define MBEDTLS_ECP_DP_SECP256R1_ENABLED
#define MBEDTLS_ENTROPY_C
#define MBEDTLS_ENTROPY_FORCE_SHA256
#define MBEDTLS_ENTROPY_HARDWARE_ALT
#define MBEDTLS_KEY_EXCHANGE_ECDHE_ECDSA_ENABLED
#define MBEDTLS_MD_C
#define MBEDTLS_OID_C
#define MBEDTLS_PEM_WRITE_C
#define MBEDTLS_PK_C
#define MBEDTLS_PK_PARSE_C
#define MBEDTLS_PK_WRITE_C
#define MBEDTLS_SHA224_C
#define MBEDTLS_SHA256_C
#define MBEDTLS_SSL_ALPN
#define MBEDTLS_SSL_CLI_C
#define MBEDTLS_SSL_KEEP_PEER_CERTIFICATE
#define MBEDTLS_SSL_PROTO_DTLS
#define MBEDTLS_SSL_PROTO_TLS1_2
#define MBEDTLS_SSL_SERVER_NAME_INDICATION
#define MBEDTLS_SSL_SRV_C
#define MBEDTLS_SSL_TLS_C
#define MBEDTLS_X509_CREATE_C
#define MBEDTLS_X509_CRT_PARSE_C
#define MBEDTLS_X509_CRT_WRITE_C
#define MBEDTLS_X509_USE_C
```
